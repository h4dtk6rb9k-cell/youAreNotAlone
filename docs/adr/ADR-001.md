# ADR-001: Архитектура экрана персонализации и генерации стартовых предметов

## Статус: Принято

## Контекст

Перед стартом игры игрок заполняет государственный бланк (ФИО, пол, возраст, профессия, место работы и др.). Данные из бланка должны:
1. Подставляться в диалоги (имя игрока)
2. Определять стартовый набор из трёх предметов в инвентаре
3. Сохраняться на протяжении всей сессии

Стек: Godot 4, GDScript.

## Решение

### Структура данных

```gdscript
# data/player_profile.gd
class_name PlayerProfile
extends Resource

@export var first_name: String = ""
@export var last_name: String = ""
@export var patronymic: String = ""
@export var gender: int = 0          # 0 = М, 1 = Ж
@export var age: int = 30
@export var education: int = 0       # 0=Среднее, 1=Ср.спец., 2=Высшее
@export var marital_status: int = 0
@export var has_children: bool = false
@export var profession: int = 0      # см. перечень ниже
@export var workplace: int = 0
@export var favorite_book: String = ""

# Profession: 0=Инженер, 1=Медик, 2=Педагог, 3=МВД,
#             4=Транспорт, 5=Госслужба, 6=Торговля, 7=Безработный
# Workplace:  0=РЖД, 1=Росатом, 2=Роскосмос, 3=Почта,
#             4=МВД, 5=Армия, 6=ФСБ,
#             7=Метро, 8=ГорТранспорт,
#             9=Единство, 10=Вектор, 11=Не трудоустроен,
#             12=CITY_HOSPITAL («Городская поликлиника»),
#             13=SCHOOL («Учебное заведение»)
```

### Сохранение профиля

```gdscript
# Сохранение
func save_profile(profile: PlayerProfile) -> void:
    var config = ConfigFile.new()
    config.set_value("profile", "first_name", profile.first_name)
    config.set_value("profile", "last_name", profile.last_name)
    config.set_value("profile", "profession", profile.profession)
    config.set_value("profile", "workplace", profile.workplace)
    config.set_value("profile", "has_children", profile.has_children)
    config.set_value("profile", "favorite_book", profile.favorite_book)
    # ... остальные поля
    config.save("user://player_profile.cfg")

# Загрузка
func load_profile() -> PlayerProfile:
    var config = ConfigFile.new()
    if config.load("user://player_profile.cfg") != OK:
        return PlayerProfile.new()
    var p = PlayerProfile.new()
    p.first_name = config.get_value("profile", "first_name", "")
    p.profession  = config.get_value("profile", "profession", 0)
    # ... остальные поля
    return p
```

### Генерация стартовых предметов

```gdscript
# core/item_factory.gd
class_name ItemFactory

static func generate_start_items(profile: PlayerProfile) -> Array:
    var items = []

    # Слот 1 — Воспоминание
    if profile.has_children:
        items.append(create_item("item_photo", profile.first_name))
    else:
        items.append(create_item(profile.favorite_book))

    # Слот 2 — Документ
    if profile.profession == 3:  # МВД
        items.append(create_item("item_badge_mvd"))
    else:
        items.append(create_item("item_badge"))

    # Слот 3 — Руководство (всегда, нельзя выбросить)
    items.append(create_item("item_guide"))

    return items
```

### Подстановка имени в диалоги

```gdscript
# core/localization.gd
func localize(raw: String) -> String:
    return raw \
        .replace("[Имя]", GameState.profile.first_name) \
        .replace("[Номер]", GameState.profile_number)
```

### Экран персонализации (Control-нода)

- Сцена: `scenes/character_creation.tscn`
- Ноды: `LineEdit` (текст), `OptionButton` (списки), `CheckButton` (пол, дети)
- Звук карандаша: `AudioStreamPlayer.play()` на каждый `text_changed`, debounce через `Timer` 50ms
- Кнопка «Подписать» (`Button`): `disabled = true` пока `first_name` или `last_name` пусты
- По нажатию: сохранить профиль → `get_tree().change_scene_to_file("res://scenes/apartment.tscn")`

## Альтернативы

**JSON через FileAccess** — рассматривалось, отклонено: ConfigFile проще для плоских данных, не требует ручного парсинга.

**Autoload-синглтон с in-memory хранением** — отклонено: данные теряются при перезапуске без явного save().

## Последствия

**Плюсы:**
- ConfigFile — нативный Godot-способ хранения настроек, хорошо документирован
- Resource-класс PlayerProfile легко расширяется (v2: внешность, история)
- localize() — единая точка подстановки имени, переиспользуется во всех диалогах

**Минусы:**
- `user://` не шифруется — данные профиля читаемы. Для пилота приемлемо.
- При изменении структуры профиля старые `.cfg` могут читаться некорректно — нужна версионность в v2.
